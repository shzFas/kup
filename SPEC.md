# kup — спецификация доски объявлений

> Версия: 0.3 (этапы 1–3 реализованы, см. README.md) · Дата: 2026-11-03
> Платформы: iOS / Android (React Native), Web (React), Backend (Go)
> Фокус: **автомобили, мотоциклы, мопеды/скутеры, квартиры**, с мощной фильтрацией по любым характеристикам.
> Рынок: **Чехия**, основная аудитория — русско- и украиноязычные жители Чехии (плюс чехи). Языки: ru (по умолчанию), uk, cs, en. Валюта CZK.

**Что важно для СНГ-аудитории в Чехии** (учтено в схемах и фильтрах):
- язык общения с продавцом (`seller_langs`) — фильтр «продавец говорит по-русски / по-украински»;
- квартиры: «можно иностранцам» (`foreigners_ok`), «возможна прописка» (`address_registration`, закреплённый фильтр), залог и коммунальные платежи отдельно от аренды, комиссия агентства;
- авто: STK, происхождение (CZ / импорт), возможность вычета НДС, евро-норма;
- подсказки (`hint`) у полей и фильтров объясняют местные термины: 2+kk, STK, SPZ, osobní vlastnictví / družstevní, energetický štítek, водительские категории AM/A1/A2;
- поисковые подсказки понимают города и марки на любом из 4 языков, без диакритики и с разговорными формами («Пльзень» = Plzeň = plzen, «бэха», «фольц»).

## 1. Цели и границы

### 1.1. Цели продукта
1. Пользователь за ≤ 3 действия находит нужное объявление благодаря глубоким фильтрам по характеристикам категории.
2. Подача объявления за ≤ 3 минуты: форма строится из схемы категории, часть полей заполняется автоматически (VIN, справочник марок/моделей, адрес по карте).
3. Сохранённые поиски с уведомлениями о новых подходящих объявлениях.
4. Одна логика фильтров для mobile и web: UI фильтров рендерится из схемы, которую отдаёт бэкенд.

### 1.2. В рамках MVP
- Категории: Легковые авто, Мотоциклы, Мопеды и скутеры, Квартиры (продажа и аренда).
- Поиск, фильтры, сортировка, карта.
- Подача/редактирование/снятие объявлений, фото.
- Авторизация по телефону (OTP), профиль, избранное, сохранённые поиски.
- Чат покупатель ↔ продавец.
- Модерация (автоматическая + ручная), жалобы.
- Админ-панель (часть web-приложения).

### 1.3. Вне MVP (позже)
- Платное продвижение (поднятие, VIP, выделение) и биллинг.
- Онлайн-оплата и безопасная сделка.
- Проверка истории авто по VIN через внешних провайдеров (в MVP — только декодирование VIN).
- Кабинет для дилеров/агентств, импорт фидов (XML/CSV).
- Дополнительные категории (коммерческая недвижимость, дома, грузовики, запчасти).

### 3.1. Принципы
- **Полная изоляция**: всё своё и self-hosted. Никаких сторонних SaaS, CDN, внешних шрифтов, аналитики и телеметрии; внутренняя сеть без выхода в интернет. Неизбежные внешние каналы (SMS для OTP, APNs/FCM, сторы приложений) — только через наш собственный адаптер и явно перечислены.
- **Модульный монолит на Go** в MVP: один бинарь, модули с чёткими границами (`listings`, `search`, `users`, `chat`, `media`, `moderation`, `notifications`). Выделение в сервисы — по нагрузке.
- **PostgreSQL — источник истины**, OpenSearch — производный индекс для поиска. Синхронизация через transactional outbox → NATS JetStream → indexer.
- **Схема категорий управляет всем**: валидацией, формой подачи, фильтрами, индексом поиска.
- **Контракт API — OpenAPI 3.1**, из него генерируются TS-типы и клиент для mobile/web.

## 4. Модель категорий и атрибутов (ядро фильтрации)

Каждая категория описывается **схемой атрибутов**. Схема хранится в БД, редактируется в админке, отдаётся клиентам через `GET /v1/categories/{slug}/schema` и кешируется (ETag).

### 4.1. Типы атрибутов

| Тип | Пример | Фильтр | Хранение в индексе |
|---|---|---|---|
| `int` / `decimal` | год, пробег, площадь | диапазон от–до | numeric |
| `enum` | коробка передач | мультивыбор (чекбоксы) | keyword |
| `multi_enum` | опции (ABS, подогрев) | «содержит все выбранные» | keyword[] |
| `bool` | STK действительна, торг | переключатель | boolean |
| `ref` | марка, модель, поколение | каскадный выбор с поиском | keyword (id) |
| `text` | VIN, описание | не фильтруется (VIN — точный поиск) | text / keyword |
| `geo` | точка на карте | радиус, полигон, видимая область карты | geo_point |
| `date` | дата сдачи дома | диапазон | date |

### 4.2. Свойства атрибута

```jsonc
{
  "key": "mileage_km",
  "type": "int",
  "label": { "ru": "Пробег", "en": "Mileage" },
  "unit": "км",
  "required": true,
  "min": 0, "max": 2000000,
  "filter": {
    "widget": "range",            // range | checkbox | select | toggle | cascade | chips
    "presets": [10000, 50000, 100000, 200000],
    "position": 4,                 // порядок в панели фильтров
    "pinned": true,                // показывать в быстрых фильтрах над выдачей
    "facet": false                 // считать количество по значениям
  },
  "depends_on": null,              // { "key": "condition", "values": ["used"] } — показывать только для б/у
  "group": "main"                  // группа в форме и в фильтрах
}
```

### 4.3. Хранение
- `listings.attributes JSONB` — значения атрибутов. Валидируются в Go по схеме категории при создании/редактировании.
- Ключевые для SQL-запросов поля денормализованы в отдельные колонки (`price`, `currency`, `year`, `geo`), остальное — только в OpenSearch.
- Схема версионируется (`category_schema_versions`), объявление хранит версию, по которой было создано. Миграция значений — фоновой задачей.

### 4.4. Справочники (`ref`)
- Авто: марка → модель → поколение → модификация (двигатель, мощность, привод, коробка). При выборе модификации форма подачи заполняет технические поля автоматически.
- Мото/мопеды: марка → модель.
- Недвижимость: город → район → микрорайон, станции метро, жилые комплексы.
- Справочники загружаются импортом (CSV/JSON) и редактируются в админке. Пользователь может предложить отсутствующую модель — уходит модератору.

## 6. Поиск и фильтрация

### 6.1. Формат фильтра (единый для API и URL)

Клиент собирает фильтр в объект, `packages/filters` сериализует его в URL (web — для SEO и шаринга, mobile — для deep links):

```
/cars?make=toyota,bmw&model=camry&year=2015..2020&mileage_km=..100000
     &fuel=petrol,hybrid&transmission=automatic&options=abs,heated_seats
     &origin=cz&price=..400000&currency=CZK&sort=price_asc&city=praha
```

Правила:
- `a..b` — диапазон, `..b` — до, `a..` — от.
- `x,y` — OR внутри одного атрибута, разные атрибуты — AND.
- `multi_enum` — AND по значениям (`options=abs,esp` → есть и ABS, и ESP).
- Каскад «марка+модель+поколение» с OR между группами: `vehicle=toyota:camry:xv70|bmw:5:f10`.
- Гео: `bbox=lat1,lng1,lat2,lng2` | `near=lat,lng&radius_km=10` | `polygon=<encoded polyline>`.

Тело запроса к API:

```http
POST /v1/search
{
  "category": "cars",
  "query": "камри",
  "filters": {
    "make": { "in": ["toyota"] },
    "year": { "gte": 2015, "lte": 2020 },
    "mileage_km": { "lte": 100000 },
    "options": { "all": ["abs", "heated_seats"] },
```

### 6.2. Требования к фильтрам
- **Счётчик «Показать N объявлений»** обновляется при каждом изменении фильтра (дебаунс 300 мс, `POST /v1/search/count`).
- **Фасеты с количеством** рядом со значениями enum; значения с нулём — приглушены, но доступны.
- Фасеты считаются по принципу **«все фильтры, кроме текущего»** (post_filter + отдельные aggregations), чтобы при выборе «Toyota» другие марки не исчезали.
- **Быстрые фильтры** (`pinned`) — горизонтальная лента чипов над выдачей.
- **Полная панель фильтров** — экран (mobile) / боковая панель (web), сгруппированная по `group`.
- Сброс одного фильтра (крестик на чипе) и всех сразу.
- Фильтры, зависящие от других (`depends_on`), скрываются, и их значения сбрасываются при смене родителя.
- Смена категории сохраняет общие фильтры (цена, гео) и сбрасывает специфичные.
- Нечёткий полнотекстовый поиск с морфологией (ru/en/kk-анализаторы) и транслитерацией («камри» ↔ «camry»).
- Подсказки в поисковой строке: категории, марки/модели, ЖК, районы (`GET /v1/suggest?q=`).
- Пагинация курсором (`search_after`), бесконечная прокрутка.

### 6.3. Карта
- Режим «список / карта» для всех категорий, основной для квартир.
- Кластеризация на сервере (geohash_grid aggregation) при отдалении, отдельные маркеры с ценой при приближении.
- Рисование области пальцем/мышью → фильтр `polygon`.
- Поиск «в этой области» при перемещении карты.

### 6.4. Сохранённые поиски и уведомления
- Любой набор фильтров можно сохранить с названием.
- Частота уведомлений: сразу / раз в день / выключено. Каналы: push, email.
- Реализация: каждый сохранённый поиск регистрируется как запрос в **OpenSearch percolator**. Новое или подешевевшее объявление проверяется против percolator при индексации → событие в NATS → worker уведомлений (с дедупликацией и тихими часами).
- В приложении — бейдж «N новых» на сохранённом поиске.

### 6.5. Индекс OpenSearch
- Отдельный индекс на каждую категорию (`listings_cars_v3`) + алиас. Маппинг генерируется из схемы категории.
- Переиндексация при изменении схемы: новый индекс → полная заливка → переключение алиаса.
- В индекс попадают только `status = active`.
- Задержка от публикации до появления в поиске: p95 ≤ 5 с.

## 7. Объявление

### 7.1. Жизненный цикл

```
draft → pending_moderation → active → (sold | archived | expired)
                ↓                ↓
             rejected         blocked
```
- Срок размещения: 30 дней (транспорт), 30 дней (продажа квартир), 14 дней (аренда); продление в один тап, push за 3 дня до окончания.
- `sold` — «Продано на kup» / «Продано в другом месте» (для статистики).
- Редактирование цены не отправляет на повторную модерацию; изменение фото, описания или ключевых атрибутов — отправляет.
- **История цен** хранится и показывается в карточке графиком.

### 7.2. Подача объявления (wizard)
1. Категория (с подсказкой по введённому тексту / VIN / адресу).
2. Ключевые характеристики (для авто: VIN или марка → модель → поколение → модификация).
3. Остальные атрибуты (форма из схемы, сгруппированная, обязательные — сверху).
4. Фото: до 30 (транспорт), до 40 (квартиры); перетаскивание для порядка, выбор обложки. Видео-ссылка (YouTube) опционально.
5. Цена, валюта, торг, обмен.
6. Местоположение (адрес с автодополнением, пин на карте; для квартир — точный адрес, публично можно показывать с точностью до дома или района).
7. Описание, контакты (звонки: да/нет, чат: да/нет, скрыть номер — подменный номер после MVP).
8. Предпросмотр → публикация.

- Черновик сохраняется автоматически на сервере после каждого шага.
- Фото загружаются напрямую в S3 по presigned URL, параллельно, с повторными попытками; на клиенте — сжатие до 2560 px по длинной стороне.

### 7.3. Карточка объявления
- Галерея (полноэкранная, zoom), количество фото.
- Цена, история цен, бейдж оценки цены, «Торг».
- Ключевые параметры (иконки), полные характеристики сгруппированно.
- Описание, адрес / карта.
- Продавец: имя, на сайте с, количество объявлений, время ответа, рейтинг (после MVP), «Частник / Компания».
- Кнопки: позвонить, написать, в избранное, поделиться, пожаловаться.
- Похожие объявления (тот же поиск по ключевым атрибутам).
- Счётчик просмотров (всего / сегодня), дата публикации и обновления.

## 8. Пользователи и авторизация
- Вход по номеру телефона + SMS OTP (4 цифры, TTL 5 мин, ≤ 5 попыток, rate-limit по номеру и IP). Социальные логины не используем (требование изоляции).
- Токены: access JWT (15 мин) + refresh (30 дней, ротация, хранится хэш в БД). Mobile — SecureStore, web — httpOnly cookie.
- Профиль: имя, аватар, город, способы связи.
- Мои объявления: активные / на модерации / черновики / архив, статистика просмотров, контактов, добавлений в избранное.
- Избранное с отметкой изменения цены.
- Чёрный список пользователей в чате.
- Удаление аккаунта (обязательно для App Store / Google Play).

## 9. Чат
- Диалог привязан к объявлению: (`listing_id`, `buyer_id`, `seller_id`).
- WebSocket для real-time; при отсутствии соединения — push.
- Сообщения: текст, фото, геопозиция; статусы «доставлено / прочитано»; «печатает…».
- Шаблоны быстрых вопросов покупателя («Ещё актуально?», «Торг возможен?», «Когда можно посмотреть?»).
- Антиспам: лимит новых диалогов в час, детекция ссылок и номеров телефонов на мошеннические ресурсы, предупреждения о предоплате.

## 10. Модерация и безопасность
- **Автомодерация** при публикации: стоп-слова, дубликаты (perceptual hash фото + похожий текст), подозрительно низкая цена относительно оценки, фото с чужими водяными знаками, контакты в описании.
- Результат: `auto_approve` / `manual_review` / `auto_reject` с причиной.
- **Ручная модерация** в админке: очередь с приоритетами, горячие клавиши, шаблоны причин отклонения, история действий модератора.
- Жалобы пользователей с категориями (мошенничество, неверная цена, продано, дубликат, неверная категория).
- Блокировка пользователя: теневая / полная; блокировка по устройству и номеру.
- Rate limits: подача объявлений, сообщения, OTP, поиск (защита от парсинга).
- Удаление EXIF и геометок из фото.

## 13. Клиенты

### 13.1. Mobile (React Native / Expo)
Вкладки: **Главная** (поиск, категории, недавно просмотренные, рекомендации) · **Избранное** (объявления / поиски) · **Подать** · **Сообщения** · **Профиль**.

- Экран фильтров рендерится из схемы категории (один компонент `<FilterRenderer schema={...} />` с виджетами `range`, `checkbox`, `cascade`, `chips`, `toggle`, `map-polygon`).
- Схемы и справочники кешируются офлайн (TanStack Query persist + ETag).
- Deep links / universal links: `kup://cars?...` и `https://kup.<домен>/cars?...` открывают ту же выдачу.
- Push: новые сообщения, совпадения по сохранённым поискам, снижение цены в избранном, окончание срока объявления.
- Производительность: выдача на FlashList, 60 fps при прокрутке, холодный старт ≤ 2 с на среднем Android-устройстве.
- OTA-обновления — только через собственный update-сервер (expo-updates поддерживает свой URL), EAS не используем.

### 13.2. Web (React / Next.js)
- SSR для страниц выдачи и карточек; SEO-страницы: `/cars/toyota/camry`, `/apartments/praha/2kk`, `/mopeds/bez-prav` и т. п. с уникальными title/description, хлебными крошками, schema.org (`Car`, `Product`, `Offer`, `Apartment`), sitemap.
- Фильтры синхронизированы с URL (назад/вперёд работают, ссылку можно отправить).
- Адаптивная вёрстка: от 360 px до десктопа; на десктопе — боковая панель фильтров + список + опционально карта рядом.
- Админка `/admin`: модерация, жалобы, редактор схем категорий (визуальный конструктор атрибутов и фильтров с предпросмотром), справочники, пользователи.
- Core Web Vitals: LCP ≤ 2.5 с, CLS ≤ 0.1, INP ≤ 200 мс.

### 13.3. Общий код
- `packages/api-client` — генерируется из `openapi.yaml` (orval или openapi-typescript), используется обоими клиентами.
- `packages/filters` — типы фильтров, сериализация в URL и обратно, вычисление зависимостей `depends_on`, человекочитаемые подписи чипов. Покрыт юнит-тестами.
